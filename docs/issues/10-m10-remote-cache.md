# M10 · 远端文件本地内容缓存

- **状态**：已完成（2026-09-23）
- **依赖**：M9
- **关联文档**：[功能设计](../functional-design.md) §5.6（远端文件）、§8.1（Binding API）、§10（边界）、§11 决策 14~17

## 目标

M9 让远端日志可以直连查看，代价是**每次重新打开都要把文件完整传一遍**（远端文件在服务端被追加/轮转后重新打开也一样）。本里程碑把读过的远端内容缓存到本机：**第二次打开与后续翻页都不再走网络**。

已确认的三项决策：

| 项 | 结论 |
|---|---|
| 缓存什么 | **文件内容**（不只是行索引）——这样重开与翻页都是本地读 |
| 默认状态 | **默认开启**，可全局关闭，也可按主机单独设置 |
| 内容变化 | 指纹（大小 + 修改时间）变化时**整份重下**，不做增量追加、不做锚点校验 |

第三条把设计大大简化：**缓存文件永远只有「某个指纹下字节级完整的副本」与「不存在」两种状态**，命中判定只有两态，不存在「前缀可信吗」的中间状态。

## 详细实现

### 1. 复合来源（`internal/filecache`）

`logfile.Source` 接口（M9 抽出的）在这里第二次发挥作用——**没有改动 `logfile` 一行**：

```go
// File 实现 logfile.Source：本地缓存 + 远端来源的组合。
// 远端来源惰性打开：命中缓存时整场只花一次 stat 往返，不开数据句柄。
func (f *File) ReadAt / Read / Seek / Stat / Close
```

- `Stat()` 返回**远端**信息，因此「打开时刻大小快照」语义与是否启用缓存无关，服务层的比较逻辑原样成立。
- **顺序读**先消费已就绪的本地前缀（读取长度夹到 `written`，否则 `.part` 的未写区域会返回 EOF，调用方会误判成文件结束），越界后转远端并**边读边写**；**随机读**落在已就绪区间时直接读本地。
- 远端流的位置可能与本地游标不一致（本地前缀那部分没有消耗远端流），因此从远端读之前先按 `pos` 定位，否则会把开头内容再读一遍。
- 缓存的写盘发生在**索引 goroutine 自己的 `Read` 里**，不另起写协程：索引中途关闭时写入自然停止，`Close` 只需丢弃未完成的 `.part`。

### 2. 生命周期与判定

- 内容：`os.UserCacheDir()/logviewer/cache/<sha256(来源键)[:16]>.bin`。
  用 `UserCacheDir`（Windows 上 `%LocalAppData%`）而不是 `UserConfigDir`（`%AppData%\Roaming`）：**漫游配置会被域环境同步到服务器**，几 GB 日志缓存不能进去。测试用 `LOGVIEWER_CACHE_DIR` 隔离。
- 写入先落 `<hash>.<pid>.<rand>.part`（**每个写入者独占命名**：固定名会让两个写入者写同一个 inode，先完成的一方改名走、后一方仍在写，已发布的 `.bin` 会被继续改写），读满快照大小后 `Truncate(size)` + `Sync()` + `Rename` 成 `.bin`。`.part` 一律视为不可用，启动时清理。
- 命中：`cache_entries` 记录的大小/修改时间与远端一致，且 `.bin` 长度等于记录值。任一不符即整份重下。
- 修改时间为 0（SFTP v3 的 mtime 退化成 0）的文件不缓存：指纹只剩大小可比，同长度轮转会误判命中。
- 引用计数 + 写入权：同一来源同一时刻只允许**一个写入者**，拿不到就退化为不缓存的直连读（不等待、不共享写句柄）。逐出跳过使用中的条目，且**任何文件 I/O 都不在持锁期间做**（逐出永不阻塞，不会与 `Close` 成环）。
- **代际号**：清空缓存/删除主机时递增；在途写入者提交前校验自己的代际，不一致就丢弃——否则「清空」之后正在下载的那个文件一提交就把条目「复活」了。
- 缓存写入失败（磁盘满、目录不可写）只记日志并放弃本次缓存，**读取与索引照常**。

### 3. 「重新加载」必须绕过缓存并重写它

用户点「重新加载」恰恰是因为「大小与修改时间都没变但内容确实变了」——用缓存会把变化藏起来。因此 `ReloadFile` 走 bypass：直连远端重下，**并用新内容重写缓存**（否则刷新一次、下次打开又弹回旧内容）。

这一条同时暴露了一个状态机问题并顺带修掉：`FileSession.Reload` 原先由调用方先打开新来源、再切换并关闭旧来源，而缓存的写入权是「每个来源键一个写入者」——新旧两份重叠时新来源会**静默退化成不缓存**。现改为 `Reload(open func() (Source, error), onLine)`：**先关旧来源，再调用 open**（`reuseOrReload` 的指纹比对也改为只查元信息，不再预开来源）。

### 4. 顺手修：远端翻页的每行往返

`logfile.ReadLines` 原先逐行 `ReadAt`，远端上每行一次网络往返（一页 20 行 ≈ 1 秒）。改为**按 ≤1MB 窗口连续读、窗口内按偏移切分**。注意不能写成「区间大于阈值就回退逐行」：`exportHits` 会把连续命中合并成一次大区间调用，`count` 可能上万行——窗口分段让往返降到「区间/窗口」次且内存有界。

同时修掉一个既有的静默错误：短读原先被吞掉，缺失部分按空行返回（更早的逐行实现里表现为静默的 NUL 垃圾行）。现在短读明确报「文件内容已变化…请重新加载」。

### 5. 前端

- 侧栏「远程主机」区底部新增「本地缓存」入口（显示条目数与占用）。
- `CacheModal`：全局开关、上限（MB）、占用与条目列表（远端路径/大小/最近使用/使用中标记）、逐条删除、一键清空。
- `ConnectModal` 增加每主机三态缓存选项（跟随全局/启用/不启用）。
- `BrowseModal` 对已缓存的文件打「已缓存」标记。
- 索引中的提示语区分「从本地缓存重建索引」与「从远端读取并缓存到本机」。

## 风险与注意

1. **默认开启改变了 M9 的隐私承诺**：远端日志可能含敏感信息，现在会落到本机磁盘。缓解见 §5.6「隐私」；不做增量续传使 `.bin` 恒为完整副本，但**同大小同修改时间的原地改写会命中陈旧缓存**，这是指纹判定的已知限制，靠「重新加载」绕过。
2. 命中判定需要一次远端 stat，因此**离线时缓存用不上**（拿不到指纹就无从判断是否最新）。这是刻意的取舍：不做「离线快照」模式，避免用户以为看到的是最新内容。
3. 下载期间的磁盘占用不计入逐出统计，上限是「已发布条目」的上限。
4. SFTP v3 的修改时间是秒级：同秒内的改写判定不出来（同上，靠强制刷新）。
5. 修正过一处 `Reload` 的状态机：必须先关旧来源再开新的，否则缓存的写入权会让新来源静默退化。
